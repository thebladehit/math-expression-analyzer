# Аналізатор та оптимізатор арифметичних виразів

Програма на Go, яка читає арифметичний вираз і проводить його через кілька етапів:

1. лексичний і синтаксичний аналіз (кінцевий автомат) — список помилок з позиціями;
2. перетворення у постфіксну форму;
3. побудова дерева виразу;
4. спрощення (алгебраїчні оптимізації);
5. генерація еквівалентних форм за законами комутативності та асоціативності;
6. побудова паралельної форми — дерева мінімальної висоти.

Якщо на першому етапі знайдено помилки, програма друкує їх і зупиняється.

## Запуск

```bash
go run .
```

Програма попросить ввести вираз. Можна передати його й через stdin:

```bash
echo 'a*1+b-c*(d+0)' | go run .
```

Кольоровий вивід вмикається лише в терміналі. Щоб вимкнути його вручну, задайте `NO_COLOR=1`.

Тести:

```bash
go test ./...
```

## Що підтримується

- числа: `2`, `3.14`
- змінні: літери, цифри та `_`, починаються з літери (`x`, `x1`, `my_var`)
- функції: `sin`, `cos`, `abs`
- операції: `+ - * /`, унарний мінус (`-a`, `(-b)`)
- дужки `( )`

## Які помилки знаходить

- **порожній вираз**
- **на початку виразу** — `*a`, `)a`
- **у написанні** — `1.2.3`, `2abc`, невідомі символи (`@`), невідомі функції (`foo(x)`)
- **у кінці виразу** — `a+`, `sin`
- **у середині** — `a++b`, `(a)(b)`, `2(a)`, `(*a)`
- **з дужками** — `((a)`, `a)`, `()`

## Структура проєкту

| Пакет | Що робить |
|---|---|
| `an/` | лексер, парсер (кінцевий автомат), типи токенів і помилок |
| `postfix/` | перетворення токенів у постфіксну форму |
| `tree/` | вузол дерева, побудова з постфіксу, малювання, перетворення назад в інфіксний запис |
| `simplifier/` | спрощення дерева |
| `group/` | спільна логіка для груп операцій `+/-` і `*//` |
| `commute/` | форми за законом комутативності |
| `associate/` | форми за законом асоціативності |
| `parallel/` | паралельна форма дерева |
| `main.go`, `print.go` | запуск усіх етапів і форматований вивід |

## Як це працює

### Аналіз

1. **Лексер** (`an/lexer.go`) розбиває рядок на токени: `CONST`, `VAR`, `FN`, `OP`, `UNARY_M`, `OB`, `CB` і `END` — маркер кінця виразу.
2. **Парсер** (`an/parser.go`) проганяє токени через кінцевий автомат (патерн State). Таблиця переходів `стан × тип токена → наступний стан + помилка` лежить у `an/state.go`. Після помилки автомат продовжує роботу, тож знаходить усі помилки, а не лише першу.
3. **Дужки** перевіряються стеком позицій. Так видно, яка саме дужка не закрита.

### Постфіксна форма та дерево

- `postfix/` реалізує алгоритм сортувальної станції: пріоритет `+ -` = 1, `* /` = 2, унарний мінус = 3; функції виштовхуються після закриття своєї дужки. Унарний мінус у виводі позначено як `-u`.
- `tree/` будує дерево зі стека постфіксних токенів. Бінарні операції мають два нащадки, функції та унарний мінус — один (`Left`).
- Дерево малюється псевдографікою з номерами ярусів, ділення показується як `÷`.
- `tree.ToInfix` перетворює дерево назад у рядок з мінімально потрібними дужками.

### Спрощення

`simplifier/` обходить дерево знизу вгору і застосовує правила:

- обчислення констант: `2*3 → 6`, `-(5) → -5` (ділення на 0 не обчислюється);
- `x*0`, `0*x → 0`;
- `x*1`, `1*x → x`, `x/1 → x`;
- `0/x → 0` (за умови, що `x ≠ 0`);
- `x+0`, `x-0`, `0+x → x`.

Кожне застосоване правило записується в журнал оптимізацій з позицією у виразі.

### Групи операцій

`group/` розглядає `+/-` та `*//` як групи з прямою та оберненою операцією. `Collect` розгортає ланцюжок однієї групи у плаский список операндів з позначкою «обернений»: наприклад, `a-b+c` → `[+a, ~b, +c]`, а `a/(1/b)` → `[+a, +b]`. `Negate` будує обернений елемент: `-x` для додавання, `1/x` для множення.

### Еквівалентні форми

- **Комутативність** (`commute/`) — перебирає всі перестановки операндів кожної групи (рекурсивно, з урахуванням підвиразів). Перший операнд з оберненим знаком отримує `-x` або `1/x`.
- **Асоціативність** (`associate/`) — перебирає всі способи розставити дужки в ланцюжку операндів групи, правильно змінюючи знаки: `a-b-c ↔ a-(b+c)`.
- **Обидва закони** — до кожної комутативної форми застосовуються асоціативні.

Дублікати прибираються за інфіксним записом (`tree.Unique`). Кількість форм обмежена `formsLimit = 5000` (`main.go`).

### Паралельна форма

`parallel/` для кожної групи збирає операнди і жадібно об'єднує два найнижчі піддерева (за висотою), поки не залишиться одне. Так дерево стає збалансованим і кількість ярусів — мінімальною: `a+b+c+d` (3 яруси) → `(a+b)+(c+d)` (2 яруси).

## Приклади

Вираз з помилками:

```
  *a++b)
  ^  ^ ^
✗ Знайдено помилок: 3
  1. [поз. 1] Вираз не може починатися з операції '*'
  2. [поз. 4] Повторна операція '+'
  3. [поз. 6] Зайва закриваюча дужка ')'
```

Коректний вираз `a*1+b-c*(d+0)` (скорочено):

```
Постфіксна форма: a 1 * b + c d 0 + * -

Дерево виразу до оптимізацій:
3          ___-___
          /       \
2       _+         *_
       /  \       /  \
1     *    \     /    +
     / \    |   |    / \
0   a   1   b   c   d   0
ярусів: 3

Оптимізації:
  1. множення на 1 (поз. 2)
  2. додавання/віднімання 0 (поз. 11)

Дерево виразу після оптимізацій:
2       __-__
       /     \
1     +       *
     / \     / \
0   a   b   c   d
ярусів: 2

Форми за законом комутативності (12):
   1. a+b-c*d
   2. a+b-d*c
   3. a-c*d+b
   ...

Форми за законом асоціативності (2):
   1. a+(b-c*d)
   2. a+b-c*d

Форми за обома законами (24):
   ...
```
